## 一个模型，两条收费路径

同一个模型，官方同时卖两种东西：

- **订阅**：固定月费，换一个窗口内可以发多少次请求。
- **API Key**：无月费，换一个账户余额，按实际 token 扣。

它们之间没有折算关系。你有 Plus，不代表 API 便宜一分；你充了 API，也不代表客户端能用得更久。

## 订阅买的是“窗口内的次数”

订阅的额度从来不是一个总数，而是**滚动窗口里的可用量**。看文档时注意三个词：

- **窗口长度**：常见是 5 小时，也有按周设上限的产品线。
- **重置方式**：滚动重置（用掉的位置随时间逐渐恢复），不是每天零点清零。
- **降级策略**：窗口用尽后，有的产品把你切到更小的模型，有的直接让你等。

这解释了为什么“我明明没用多少”和“额度没了”会同时成立：短时间集中使用会撞窗口，而窗口是按时间滑动的。

## API 买的是精确的用量

API 的账单可以逐条对上，因为它按 token 计量，并且分了几个价位：

| 计费项 | 说明 |
| --- | --- |
| 输入 token | 你发过去的全部内容：系统提示、历史消息、读进来的文件 |
| 缓存命中的输入 | 重复前缀命中缓存时按更低价格计 |
| 输出 token | 模型生成的内容，单价通常高于输入 |

对写代码这件事来说，**输入往往是大头**，因为每一轮都要把上下文重新送进去。这也是为什么“多读几个文件”这个动作在账单上比“多问几个问题”更贵。

## 决策树：三种需求，三种买法

**一、我自己天天在网页或终端里用**

买订阅。月费换的是不限次数的体验和更高的额度窗口，只要是人在用，单价几乎总是比 API 便宜。

**二、我要接进程序、脚本、自动化流水线**

买 API。订阅不能给程序当接口用，这一点没有变通。

**三、两者都要**

两份钱都花。这不是重复付费：一份买交互，一份买调用能力。多数把 AI 接进日常开发的团队最后都停在这个状态。

## 换算：一次编码会话大概多少钱

不给假精确，给区间和判断方法。

一次中等规模的编码会话——读四五个文件、来回三到五轮、最后跑一次测试——通常落在**几万到十几万输入 token、几千输出 token**。按当前主流定价换算，大致是**几美分到几十美分**。

对照订阅：一个月 20 美元的订阅，如果每天跑十次这样的会话，相当于每天不到 0.7 美元。所以判断标准其实很朴素：

> 人用，订阅划算；程序用，API 划算；让程序去消耗订阅额度，两头都不划算。

想看真实数字，别估算，去看用量面板：客户端里有账户用量页，API 侧有账单明细。**唯一可信的换算来自你自己的用量**。

## 四个反复出现的坑

**一、Key 被提交进 git**

公开仓库里被扫到只是时间问题，扫到之后按量刷是自动化的。规则很简单：Key 只在环境变量里，`.env` 必须在 `.gitignore` 里，一旦疑似泄露立刻吊销重建，不要试图“观察一下”。

**二、个人账号与组织账号额度不互通**

团队里有人用自己的账号跑 CI，账单散在个人账单上，月底对不上。定一条：自动化一律走组织级 Key。

**三、免费额度到期不降级**

API 侧的免费额度用尽后，请求直接失败，不会悄悄换成便宜模型。所以流水线里要有对 `429` 和额度错误的显式处理，而不是等它超时。

**四、把 API Key 当登录凭据**

API Key 不能登录网页版和桌面客户端。反过来，用订阅账号去配置第三方工具时，很多工具要的是 Key，不是账号密码——这类“配不通”的问题多半是选错了凭据类型。
