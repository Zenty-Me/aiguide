## 先把“成本”这个词拆开

大多数人比较渠道时只看一个数字：标价。但真实成本包含三项，缺一项就会算错。

1. **标价**：你付出去的那一笔。
2. **失效概率 × 剩余时长**：钱花了，服务没到期就没了，这部分是沉没成本。
3. **你的时间**：处理失效、重新购买、迁移配置、恢复中断的工作。

把三项合成一个可以直接比较的指标：

```
有效月成本 = 标价 ÷ 预期可用月数 + 处理失效的时间成本
```

预期可用月数不是宣传的时长，而是**你估计它真能撑多久**。一个月付 198、大概率能用满 12 个月的方案，有效月成本约 16.5；一个月付 99、但平均两个月掉一次的方案，有效月成本是 49.5，还要加上每次重配的时间。

## 四种路径的成本结构

| 路径 | 钱花在哪 | 主要风险 | 适合谁 |
| --- | --- | --- | --- |
| 官方直订 | 全额标价 | 几乎只有涨价 | 长期用、要发票、账号里有重要数据 |
| 代充（开在你自己的号上） | 低于官方，按周期付 | 订阅被回收 | 想省钱但要保住账号归属 |
| 成品号（交付现成账号） | 最低 | 账号控制权不在你手里 | 短期、可弃、跑脚本或做实验 |
| API 按量 | 用多少付多少 | 用量失控 | 程序调用、用量可预测 |

四种不是替代关系。同一个人常常是“主力号直订 + 实验号成品 + 脚本走 API”，各自承担不同的用途，而不是把所有需求压到最便宜的那一档。

## 三种最常见的误判

**只看单价，不看单次可用时长。** 便宜一半但寿命只有三分之一，实际是贵了 50%。买之前问一句“平均能用多久”，比问“多少钱”有用得多。

**把“永久”当永久。** 任何绑定在第三方账号体系上的“永久”，上限都是平台的政策周期。政策一变、风控一收紧，永久就到期了。这类承诺要按“最多用几个月”来折算，而不是按宣传文案。

**忽略迁移成本。** 你在一个账号里攒的对话历史、项目配置、自定义指令、API Key 引用，换号时全要重来。用得越久，迁移成本越高，这部分应该算进“失效一次”的代价里。

## 怎么用这张表做决定

先回答三个问题，答案会直接指向某一档：

1. 这个账号里会不会放不能丢的东西（历史对话、代码上下文、客户数据）？会 → 控制权必须在你自己手里。
2. 每天用几次？一天十次以上 → 订阅；一周两次 → 按量或短期。
3. 失效一次，你的损失是“重买一次”还是“耽误一天工作”？后者要按时间成本加价，别选最便宜的。

算出来的结论经常和直觉相反：**用得越重，越应该买贵的；用得越轻，越应该买短的。** 中间地带才是比价真正有意义的地方。
